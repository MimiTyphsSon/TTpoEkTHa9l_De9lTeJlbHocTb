## Обоснование по проектам

### Проект 1. Мобильное приложение для доставки еды

1. **Цель:** создать работающее мобильное приложение для заказа и доставки еды.
2. **Результат:** мобильное приложение (iOS/Android), размещённое в магазинах приложений, с базой данных ресторанов и системой заказов.
3. **Ограничение по времени:** да, 4 месяца.
4. **Участники:** руководитель проекта, аналитик, мобильный разработчик, backend-разработчик, дизайнер, тестировщик.

### Проект 3. База данных для учёта студентов

1. **Цель:** создать новую базу данных для хранения и обработки информации о студентах.
2. **Результат:** спроектированная и заполненная БД с интерфейсом доступа, документацией и правами пользователей.
3. **Ограничение по времени:** да (ориентировочно 2–3 месяца).
4. **Участники:** администратор БД, аналитик, разработчик, тестировщик, представитель учебной части (заказчик).

### Проект 5. Система электронного расписания

1. **Цель:** разработать систему электронного расписания для колледжа.
2. **Результат:** веб-приложение с базой данных расписания, просмотром, поиском и отображением изменений.
3. **Ограничение по времени:** да (ориентировочно 3 месяца).
4. **Участники:** руководитель проекта, аналитик, разработчик, тестировщик, заказчик (администрация колледжа).

### Проект 7. Перенос сайта на новый сервер

1. **Цель:** перенести существующий сайт на новый сервер без потери работоспособности.
2. **Результат:** сайт, работающий на новом сервере, с сохранёнными данными и настроенным доменом.
3. **Ограничение по времени:** да (обычно 1–2 недели, чтобы минимизировать простой).
4. **Участники:** системный администратор, разработчик, тестировщик.

# Практическая работа №2. Создание концепции программного проекта

## Выбранная идея: Система электронного расписания для колледжа

## 1. Название проекта

**«SmartSchedule» — система электронного расписания колледжа**

## 2. Описание проблемы

В колледже студенты и преподаватели узнают об изменениях расписания через сообщения в групповых чатах и объявления на доске. Информация часто теряется, устаревает или доходит с опозданием. Студенты приходят не в ту аудиторию, преподаватели не знают о переносах, а администрация тратит много времени на ручное оповещение. Единой актуальной точки доступа к расписанию нет.

**У кого возникает проблема:** студенты, преподаватели, администрация колледжа.

**Почему существующий способ неудобен:** сообщения в чатах теряются, доска объявлений не всегда доступна, нет поиска по группе/преподавателю/аудитории, изменения не отображаются оперативно.

**Почему программный продукт поможет:** единая система с актуальным расписанием, доступная с любого устройства, с поиском и мгновенным отображением изменений.

## 3. Целевая аудитория

- Студенты колледжа
- Преподаватели
- Администрация (учебная часть, диспетчер расписания)

## 4. Цель проекта

Разработать веб-приложение для просмотра актуального расписания занятий, преподавателей и аудиторий с возможностью поиска по группе и отображения изменений.

## 5. Ожидаемый результат

- Веб-приложение, доступное в браузере
- База данных расписания (группы, преподаватели, аудитории, пары)
- Просмотр расписания по группе и по преподавателю
- Поиск по группе
- Отображение изменений и замен
- Административная панель для редактирования расписания

## 6. Участники проекта и их обязанности

| Роль | Ответственность |
|------|-----------------|
| Руководитель проекта | Планирование, контроль сроков, коммуникация с заказчиком |
| Аналитик | Сбор требований, описание сценариев использования, документация |
| Разработчик | Проектирование и разработка веб-приложения и базы данных |
| Тестировщик | Проверка работоспособности, тестирование сценариев, поиск ошибок |
| Заказчик | Предоставление требований, приёмка результата, обратная связь |

## 7. Предполагаемые сроки

**3 месяца** (12 недель):

- 2 недели — анализ и требования
- 2 недели — проектирование
- 5 недель — разработка
- 2 недели — тестирование
- 1 неделя — внедрение и сдача

## 8. Основные ограничения

- **Срок разработки:** 3 месяца
- **Команда:** 4 человека
- **Бюджет:** ограниченный
- **Платформа:** веб-приложение
- **Результат:** работающий программный продукт

## 9. Три возможных риска

1. **Изменение требований заказчиком** — может привести к срыву сроков. *Мера:* фиксация требований на этапе анализа, согласование изменений через руководителя проекта.
2. **Болезнь или уход ключевого разработчика** — замедление разработки. *Мера:* документирование кода, перекрёстное владение задачами, резервный разработчик.
3. **Проблемы с интеграцией данных расписания** (несовместимость форматов, неполные данные от учебной части) — задержка запуска. *Мера:* раннее согласование формата данных, тестовая выгрузка на старте проекта.

## Ответы на вопросы для представления

1. **Какую проблему решает продукт?** Отсутствие единой актуальной точки доступа к расписанию и оперативного оповещения об изменениях.
2. **Кто будет пользоваться?** Студенты, преподаватели, администрация колледжа.
3. **Что конкретно разработать?** Веб-приложение с базой данных расписания, просмотром, поиском и отображением изменений.
4. **Какие специалисты нужны?** Руководитель проекта, аналитик, разработчик, тестировщик, заказчик.
5. **Какие проблемы могут возникнуть?** Изменение требований, болезнь разработчика, проблемы с интеграцией данных расписания.

## Дополнительные ответы на возможные вопросы преподавателя

- **Почему нельзя решить проблему без программы?** Ручное оповещение через чаты и доски не гарантирует актуальность и доступность информации в нужный момент; программа обеспечивает единый источник правды.
- **Что произойдёт, если разработчик заболеет?** Задачи документированы, второй разработчик владеет ключевыми модулями; при необходимости подключается резерв.
- **Что будете делать, если заказчик изменит требования?** Проведём оценку влияния на сроки и бюджет, согласуем изменения через руководителя проекта, зафиксируем в документации.
- **Как поймёте, что проект завершён успешно?** Система развёрнута, расписание доступно студентам и преподавателям, изменения отображаются, заказчик принял результат, тестирование пройдено.
