## Оценка вероятности и влияния

Шкала: 1–5. Показатель `R = P × I`. Приоритет: 1–4 низкий, 5–9 умеренный, 10–16 высокий, 17–25 критический.

## Критические риски (три наибольших R)

### 1. R02 — Backend не успевает реализовать API (R = 16)

**Почему опаснее остальных:** API блокирует Frontend и тестирование — задержка backend останавливает половину команды.

**Какие задачи затрагивает:** API расписания, API поиска, API изменений, админ-панель, страницы Frontend, интеграционное тестирование.

**Последствия без действий:** Frontend простаивает, тестирование срывается, демонстрация заказчику не состоится в срок.

### 2. R07 — Не хватит времени на тестирование (R = 16)

**Почему опаснее остальных:** без тестирования продукт нельзя передавать заказчику; ошибки проявятся в эксплуатации.

**Какие задачи затрагивает:** функциональное тестирование, проверка прав доступа, приёмка заказчиком.

**Последствия без действий:** дефекты в расписании, недоверие пользователей, доработки после сдачи.

### 3. R11 — Не настроено резервное копирование БД (R = 16)

**Почему опаснее остальных:** потеря данных — необратимое последствие, которое может уничтожить результаты всей разработки.

**Какие задачи затрагивает:** база данных расписания, развёртывание, эксплуатация.

**Последствия без действий:** при сбое сервера данные расписания теряются, продукт невозможно восстановить.

# Практическая работа №2. План реагирования и контроль проекта

**Проект:** «SmartSchedule». До демонстрации заказчику — 10 рабочих дней.

## Определение проблем и рисков

### Уже возникшие проблемы

| № | Обстоятельство                                             | Проблема                                          |
| - | ---------------------------------------------------------- | ------------------------------------------------- |
| 1 | Backend-разработчик отстаёт на 3 дня                       | Задержка API, риск срыва демонстрации             |
| 2 | Frontend завершил интерфейс, но не может подключить API    | Блокировка Frontend, простой                     |
| 3 | Тестировщик не получил готовую сборку                      | Тестирование не начато                            |
| 5 | Ошибка в структуре хранения расписания                     | Данные могут быть некорректны, API зависит от БД  |
| 6 | Резервное копирование не настроено                         | Риск потери данных при сбое                       |

### Потенциальные риски

| № | Обстоятельство                                             | Риск                                              |
| - | ---------------------------------------------------------- | ------------------------------------------------- |
| 4 | Заказчик просит экспорт в PDF                              | Расширение объёма работ, срыв сроков              |
| 1 | Backend отстаёт                                            | Задержка может увеличиться, если не принять меры  |
| 2 | Frontend без API                                           | Простой может затянуться, если API не будет готов |
| 3 | Нет сборки                                                 | Тестирование может не успеть до демонстрации      |
| 6 | Нет резервного копирования                                 | Потеря данных при сбое во время демонстрации      |

**Что может произойти дальше:** если backend продолжит исправлять БД без приоритета API, Frontend и тестировщик будут простаивать; если добавить PDF сейчас — сроки сдвинутся; если не настроить резервное копирование — сбой сервера уничтожит данные.

## План реагирования

| Обстоятельство                     | Решение                                                                                   | Стратегия           |
| ---------------------------------- | ----------------------------------------------------------------------------------------- | ------------------- |
| Backend отстаёт на 3 дня           | Приоритет: сначала закрыть ошибку БД, затем API по согласованному контракту; ежедневный контроль | Снижение            |
| Frontend не может подключить API   | Перевести Frontend на mock API по согласованному контракту; после готовности API — замена на реальный | Снижение            |
| Тестировщик без сборки             | Передать промежуточную сборку с mock-данными для подготовки тестовых сценариев и проверки готовых модулей | Снижение            |
| Заказчик просит экспорт в PDF      | Вынести PDF за границы текущего этапа; согласовать перенос на следующий этап или отдельную задачу после демонстрации | Избегание (перенос) |
| Ошибка в структуре БД              | Исправить в первую очередь (блокирует API); Backend — ответственный; проверить корректность данных | Снижение            |
| Резервное копирование не настроено | Настроить ежедневное резервное копирование в первый же день; проверить восстановление     | Снижение            |

### Изменение последовательности задач

1. День 1: исправление структуры БД + настройка резервного копирования + согласование контракта API.
2. День 2–4: Backend завершает API по контракту; Frontend работает на mock API.
3. День 5: Frontend подключается к реальному API; тестировщик получает сборку.
4. День 6–8: тестирование, исправление ошибок.
5. День 9: финальная проверка, развёртывание.
6. День 10: демонстрация заказчику.

### Параллельная работа

- Backend исправляет БД ↔ Frontend на mock API ↔ тестировщик готовит сценарии.
- После готовности API: Frontend подключается ↔ Backend исправляет найденные баги ↔ тестировщик проверяет.

### Перенос новой функции

Экспорт в PDF **не входит** в текущий этап: согласовать с заказчиком перенос на следующий этап после демонстрации. Это защищает сроки.

## Контрольные точки

| Контрольная точка                  | Срок   | Что проверяется                                 | Ответственный       |
| ---------------------------------- | ------ | ----------------------------------------------- | ------------------- |
| Контракт API согласован            | День 1 | Эндпоинты, форматы запросов/ответов             | Аналитик + Backend  |
| Ошибка БД исправлена               | День 2 | Корректность структуры хранения расписания      | Backend             |
| Резервное копирование настроено    | День 1 | Ежедневный бэкап, проверка восстановления       | Backend             |

| API готов                          | День 4 | Все эндпоинты работают по контракту             | Backend             |
| Первая сборка передана тестировщику| День 5 | Сборка с реальным API                           | Руководитель проекта|
| Тестирование завершено             | День 8 | Основные сценарии, права доступа                | Тестировщик         |
| Продукт развёрнут                  | День 9 | Доступность системы                             | Backend             |
| Демонстрация заказчику             | День 10| Приёмка результата                              | Руководитель проекта|
